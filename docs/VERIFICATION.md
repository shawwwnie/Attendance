# 검증 기록

구현 후 실행한 결과와 실제 확인한 범위만 이 파일에 기록합니다.

## 검증 항목

- Java 컴파일과 QueryDSL Q 클래스 생성.
- 실제 PostgreSQL에 Flyway 마이그레이션 적용 및 Hibernate 스키마 검증.
- 금액 반올림·잘못된 값·연산 범위.
- 인증·CSRF·조회 권한·센터별 접근 제한.
- 월 청구와 수납의 중복 요청·동시 요청·롤백.
- QueryDSL 필터·페이지·집계.
- TypeScript 검사·프론트엔드 프로덕션 빌드.
- 수납 재시도 키 보존.
- 브라우저에서 로그인부터 수납까지 실제 API 연동.
- 오류 시 재시도, 조회 전용 계정, 다른 센터, 모바일 화면.

1. 로그인 → 가상 수급자 등록 → 오늘 일정 등록 → 이용 완료 → 청구서 발행 → 부분 수납 → 변경 이력 확인.

3. 다른 센터 계정의 별도 수급자 조회.
4. 목록 API 통신 실패 후 재시도 버튼으로 복구.
5. 잘못된 비밀번호의 로그인 오류 표시.
6. 예정 일정이 남은 청구 요청의 업무 오류를 모달 안에서 표시.
7. 390px 모바일 대시보드·청구 화면의 가로 넘침 방지와 메뉴 이동.

## 실행 환경

| 항목 | 실제 검증 환경 |
|---|---|
| Java | OpenJDK 21.0.13, 컴파일 대상 `--release 17` |
| Spring Boot | 3.5.16 |
| Maven | 3.9.11 |
| PostgreSQL | 14.15, embedded PostgreSQL의 실제 서버 프로세스 |
| Node.js | 24.22.1 |
| Vue / Vite | 3.5.45 / 7.3.8 |
| Vitest | 4.1.12 |
| Playwright / 브라우저 | 1.58.2 / Chrome Headless Shell 145.0.7632.6 |

환경에서 일반 Chromium의 로컬 소켓 생성이 제한되어, 공식 Chrome Headless Shell로 브라우저 검증을 수행했습니다. 테스트 설정은 필요하면 `CAREFLOW_CHROMIUM_PATH`로 브라우저 실행 파일을 지정할 수 있습니다. 일반 개발 환경과 CI는 Playwright가 설치한 Chromium을 기본 사용합니다.

로그인·CSRF 검증은 MockMvc의 `csrf()` 도우미가 보안 필터 저장소를 바꾸는 영향을 피하도록 별도 테스트 컨텍스트에서 실제 쿠키·토큰으로 수행했습니다.

## 아직 직접 실행하지 않은 구성

- Docker Engine이 없는 환경이므로 **Compose 전체 실행과 Docker 이미지 빌드는 미검증**입니다. Compose에는 PostgreSQL 17을 지정했으며 로컬 자동 검증에 사용한 DB는 위 표의 14.15입니다.
- CI는 Ubuntu 24.04·Java 17·Node 24로 실행 환경을 고정했습니다. 이 문서의 통과 수치는 직접 실행한 결과이며 GitHub Actions의 실행 결과는 저장소 Actions에서 별도로 확인합니다.

## 범위

Docker Engine 사용 가능 여부에 따라 Compose 자체의 실행 검증 여부를 별도로 기록합니다. 실제 공단 연동·수가 적정성·대규모 성능·실제 개인정보·장애 복구는 이 포트폴리오의 검증 범위에 포함하지 않습니다.
